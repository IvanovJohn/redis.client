# Сравнение со StackExchange.Redis

Стенд прогоняет одинаковые сценарии на Redis.Client и StackExchange.Redis: производительность и поведение при сетевых сбоях. Redis стоит за [toxiproxy](https://github.com/Shopify/toxiproxy), через который стенд вносит задержки и сбои.

```bash
cd benchmarks/Redis.Client.Comparison
docker compose up -d
dotnet run -c Release -- all          # perf + chaos, около 10 минут
dotnet run -c Release -- chaos --quick
docker compose down
```

Отчёт в Markdown и временная шкала сбоев в CSV сохраняются в `artifacts/comparison/`.

## Что измеряется

**Производительность** (`perf`): GET и SET со значениями 100 Б и 16 КБ, на localhost напрямую и через toxiproxy с задержкой +1 мс.

- **Пропускная способность.** 256 вызывающих в замкнутом цикле. Здесь же меряются CPU и аллокации на операцию.
- **Задержки.** Открытый цикл на 50% пропускной способности более медленного клиента. Время считается от запланированного момента старта запроса, поэтому клиент, который подвис и отправил меньше запросов, не получает фору (coordinated omission).

**Сбои** (`chaos`). Оба клиента работают одновременно и получают одни и те же сбои. Каждый поток записывает уникальное значение и сразу читает его обратно.

| Сценарий | Как вносится |
|---|---|
| Обрыв соединений | `reset_peer` на 1 с |
| Redis недоступен | прокси выключен |
| Сеть замерла | `timeout` с нулевым таймаутом: данные задерживаются, соединение не рвётся |
| Медленная сеть | `latency` +3 с, больше `CommandTimeout` |
| Ответы по 1 байту | `slicer`: проверка разбора фрагментированных ответов |
| Перезапуск Redis | `docker restart` |

## Ограничения

- Всё работает на одной машине. Стенд, Redis и toxiproxy конкурируют за CPU, а на WSL ещё и за сеть через docker-proxy, поэтому абсолютные числа выше, чем в реальной сети. Сравнивать имеет смысл только клиентов между собой.
- toxiproxy не умеет терять пакеты, только задерживать их. Настоящее полуоткрытое соединение проверяют интеграционные тесты клиента.
- У StackExchange.Redis используются настройки по умолчанию, кроме таймаутов. Подкрутить можно обоих клиентов.
