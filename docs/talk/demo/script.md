# Сценарий живого демо

Реплики для вставки — в [prompts.md](prompts.md). Тайминги и наблюдения — по репетиции 23.10.2026 на Haiku.

## Накануне

1. `docs/talk/demo/prepare.sh` — создаёт свежие папки `~/sdd-demo/<время>/{greenfield,brownfield}`, собирает проект и поднимает стенд (redis + toxiproxy). Занимает около 20 с, ничего не удаляет.
2. Замер «до» в `brownfield`, чтобы стенд прогрелся и цифра была перед глазами:
   `cd brownfield/benchmarks/Redis.Client.Comparison && dotnet run -c Release -- chaos --only down` — 25 с, ожидаемо ~7,9 с у Redis.Client и ~2,0 с у StackExchange.Redis.
3. Открыть два терминала (greenfield и brownfield) и IDE с репозиторием.

## Часть 1. С нуля (~6 мин)

| Шаг | Время на репетиции |
|---|---|
| `/opsx:new` + «давай сделаем клиента…» | ~20 с |
| Ответ на вопросы | до 4,5 мин: Haiku может сразу создать все 4 артефакта |

Пока агент пишет, рассказывать. Что показать:

- **proposal.md**: на репетиции Haiku раздул объём — 10 capabilities, включая Cluster, Sentinel, Streams, и 163 задачи. В нашей версии 7 capabilities и явный список «не делаем».
- **design.md**: на репетиции — противоречие «Streams (Redis 5.0+)» и рядом открытый вопрос «Redis 5.x (Streams not available)?».
- Мысль для зала: выбор модели сильно влияет на качество решений, а процесс делает это видимым на одной странице, ещё до кода.

Дальше не идём: реализация такого объёма на сцене не поместится.

## Часть 2. Исправление дефекта (~10 мин)

| Шаг | Время на репетиции | Стоимость |
|---|---|---|
| `/opsx:ff fix-reconnect-backoff: …` | 1,5 мин | $0,11 |
| Реплика ревью design | 1,5 мин | $0,12 |
| `/opsx:apply` | 2,2 мин | $0,32 |
| Замер «после» | 25 с | — |

1. **Ревью design — главный момент демо.** Haiku каждый раз предлагает разное, на репетициях было три варианта:
   - «сбрасывать счётчик попыток после подключения» — он и так сбрасывается (`attempt = 0` в `src/Redis.Client/Connections/MultiplexedConnection.cs`);
   - «базовая пауза 10 мс, рост не больше 320 мс» — восстановление быстрое, но клиент стучится в сервер трижды в секунду;
   - сразу верное: `ReconnectMaxDelay` по умолчанию 30 с → 2 с.

   На неудачный вариант — реплика с тремя проверочными вопросами из prompts.md, она не называет ответ. На верный — реплика «принимаю, два замечания» (старое значение в README и spec, тест). В любом случае ошибка ловится на странице текста, до кода.
2. **apply.** Показать дифф: исправление — одна строка в `RedisClientOptions.cs`.
3. **Замер «после».** На репетиции: 7,9 с → **0,3 с** (StackExchange.Redis 2,0 с).
4. **Проверка отчёта агента** — второй важный момент. На репетиции Haiku:
   - отметил все 27 задач, включая трассировку (не добавлена) и запуск бенчмарка (не запускал);
   - написал интеграционный тест, который ни разу не запускал, — он падает (секундомер запускается до 10-секундного простоя);
   - не обновил README и таблицу значений по умолчанию в `openspec/specs/client-configuration`.

   Отправить реплику проверки из prompts.md и показать, как агент снимает лишние отметки. Мысль для зала: отчёт агента — не доказательство; доказательство — тесты и замер.

## Если что-то пошло не так

- **API недоступен или агент ушёл не туда.** Запасной слайд `slides/18-rehearsal.png` рассказывает итоги репетиции.
- **Стенд не отвечает.** `docker compose up -d` в `benchmarks/Redis.Client.Comparison`; если toxiproxy завис — `docker restart cmp-toxiproxy`.
- **Агент просит разрешения на каждую команду.** Заранее выбрать в Claude Code режим, при котором правки файлов разрешены (Shift+Tab → accept edits).

## Стоимость

Вся репетиция обеих частей на Haiku стоила около $0,90.
