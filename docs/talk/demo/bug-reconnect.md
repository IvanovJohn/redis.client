# Промпт для живого демо: баг переподключения

Метка в репозитории: `demo/before-reconnect-fix`. `prepare.sh` создаёт рабочую копию `brownfield` от неё. Это текущий код с багом, но без папки `docs/`, чтобы агент не нашёл ответ в материалах доклада.

Вставить в Claude Code (`claude --model haiku`) в папке `brownfield` одним сообщением, от `/opsx:ff` до конца блока:

```
/opsx:ff fix-reconnect-backoff

Баг: после того как Redis снова стал доступен, клиент долго не переподключается.

Как воспроизвести:
  cd benchmarks/Redis.Client.Comparison
  docker compose up -d
  dotnet run -c Release -- chaos --only down

Сценарий «Redis недоступен 10 с»: toxiproxy на 10 секунд закрывает доступ к Redis, потом открывает его снова.

Фактически: Redis.Client восстанавливается через 7,8 с после возвращения сервера, всё это время команды падают по таймауту. StackExchange.Redis в том же прогоне восстанавливается через 2,1 с.

Ожидается: после возвращения сервера клиент переподключается не дольше чем за 2 с. Во время простоя он не должен заваливать сервер попытками подключения.

Гипотеза: дело в паузе между попытками переподключения.

Найди причину, зафиксируй решение в design, измени требования в spec и добавь тест на скорость восстановления.
```

На репетиции 23.10.2026 использовался более подробный вариант, где причина была названа прямо (см. [prompts.md](prompts.md)). С этим текстом Haiku ещё не прогонялся.
